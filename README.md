# Japan Student Management System

A local-first application for managing student profiles and education documents.

## Development foundation

### Requirements

- Windows 10/11
- Node.js 24 LTS or later
- npm 11 or later

### Start locally

```powershell
Copy-Item apps\api\.env.example apps\api\.env
npm install
npm run dev
```

Open the Vite URL shown in the terminal (normally `http://127.0.0.1:5173`). The
frontend calls the API through its development proxy; the API listens on
`127.0.0.1:3001` by default.

### PostgreSQL migrations

Install PostgreSQL 14 or later locally, create an empty `hsms_dev` database,
copy `apps\api\.env.example` to `apps\api\.env`, and replace the example
database password with your local PostgreSQL password. Do not commit `.env`.
The API still binds to localhost; PostgreSQL should not be exposed to the LAN.

Apply pending migrations or roll back the latest migration from the repository root:

```powershell
npm run migrate:up
npm run migrate:down
```

The migrations create users, roles, permissions, role assignments, hashed-token
session storage, student records, intake fields, and a private student-document
table. They also seed the Admin and Staff roles with baseline permissions. Run
rollback only when you intend to remove the tables introduced by the migration
and all data stored in them.

The API requires a valid PostgreSQL connection URL in `apps\api\.env`. Its
`/api/health` endpoint reports process liveness; `/api/ready` executes a
database query and returns HTTP 503 when PostgreSQL is unavailable. The server
drains HTTP requests and closes the connection pool during shutdown.

### Student records

After PostgreSQL is installed and the migrations have run, open the app to
search, filter, add, edit, and review student profiles. Open `/apply` on the
same PC to use the student self-intake form. The form collects a student's
name, contact number, email, one social profile link, last completed degree,
language qualification, up to five study fields, and optional document uploads.
Documents must be PDFs except for the passport photo (JPG or PNG); each file is
limited to 10 MB and the combined upload to 35 MB. Documents are stored as
private PostgreSQL `bytea` data and are downloaded through the API rather than
served as public files. Internal student IDs are generated by the API. No
sample or synthetic student records are inserted into your database.

The form is local-only: students must use this PC, and `/apply` is not a
shareable internet URL. Student data routes are currently available only
through a server bound to a loopback address. There is no separate student
login, and the staff dashboard is accessible from the same PC. Use the form
only under staff supervision; do not expose this development app to a LAN or
store real student information until authentication and authorization are
implemented.

To run checks:

```powershell
npm test
npm run typecheck
npm run build
```

### Current scope and security boundary

This increment provides a React/TypeScript frontend, Express/TypeScript API,
PostgreSQL-backed student profile list/search/create/update and self-intake
routes, database-backed private document uploads, centralized input validation
and error handling, and API/database health endpoints. Authentication,
server-side authorization, and internet/LAN deployment are not yet implemented.
Keep both development servers bound to localhost; do not expose them to a
network.

The approved design is to add server-side authorization and LAN-only deployment
in later increments. Database schema work will follow the approved Phase 0
proposal.
